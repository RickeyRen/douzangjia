# 影仓产品总体设计

## 产品定位

将现有的“留影”重构为“影仓”，副标题为“私人短视频媒体库”。影仓不是一个下载脚本面板，而是部署在 NAS 上的私人、可检索、可持续保留的短视频媒体库。

用户通过 NAS 内的专用 Chromium profile 保持已登录抖音会话，后端从该会话读取用户可见的内容，影仓前端以本地数据和本地媒体为主提供快速浏览。官方页面只是数据连接器和登录容器，不作为日常浏览 UI。

## 设计原则

1. **本地优先**：已归档媒体与元数据在抖音不可用时仍能浏览。
2. **数据可信**：远端声称数、已发现数、已入库数、已下载数分开显示，不用“同步成功”掩盖缺口。
3. **异步任务**：任何批量同步或下载都进入持久化任务队列，可观察、可暂停、可重试。
4. **连续浏览**：列表使用游标、预取和虚拟化，正常情况不出现“加载更多”按钮。
5. **隐私边界**：Chromium profile、cookie、二维码、短信码、本地数据库和媒体文件不进 Git，不出现在日志和截图归档中。
6. **尊重来源**：交互结构参考抖音网页版，但不复制官方商标、品牌素材或受保护的视觉资产。

## 信息架构

### 桌面端

- 左侧固定主导航：首页、我的、关注、媒体库、下载任务、控制台、设置。
- 顶部操作区：全局搜索、同步状态、主题切换、用户会话状态。
- 中间主区：沉浸式单作品流或高密度网格，可无缝切换。
- 右侧上下文区：作品详情、归档状态、文件明细和快捷下载操作。

### 移动端

- iPhone 15 Pro Max 基准视口为 `430 x 932` CSS px。
- 底部四项导航：首页、我的、任务、控制台。
- 沉浸视图避让 safe-area，网格默认两列；详情和筛选使用底部抽屉。
- 主要触摸目标最小 `44 x 44` CSS px。

## 全局验收标准

- 影仓能显示已登录账户的作品、喜欢、收藏夹、关注、观看历史、稍后再看与预约；不可访问的来源明确显示原因。
- 收藏夹远端数量与本地发现数可对账，差异有可点击的详情和重扫描操作。
- 用户在沉浸视图或网格中连续浏览至少 100 项，不需点击“加载更多”。
- 用户能下载单作品、整个收藏夹、某创作者全部作品，并为创作者开启自动追更。
- 控制台同时显示当前数值与历史趋势，所有任务可追溯到具体来源和失败原因。
- 桌面 Chrome 和 `430 x 932` 视口下无遮挡、横向溢出、不可点击主要操作或导航丢失。

# 抖音收藏 NAS 归档系统设计

## 1. 目标

在 fnOS NAS `192.168.0.6` 上运行一个只面向局域网的收藏归档服务。服务每 5 分钟检查一次当前抖音账号的收藏夹，将新作品在 10 分钟内下载并按抖音收藏夹名称呈现，同时提供接近抖音的本地浏览体验。

系统采用“只增不删”的归档语义：取消收藏、移动收藏、收藏夹重命名、作者删除或隐藏原作品，都不能删除已经成功写入 NAS 的媒体。

## 2. 范围

首个可用版本必须覆盖：

- NAS 内扫码登录和 Cookie 续期，不依赖 Mac。
- 账号默认收藏与所有自定义收藏夹。
- 视频、图文作品和作品元数据。
- 收藏夹名称到 NAS 展示目录的一致映射。
- 初次全量回填、每 5 分钟增量扫描、失败重试和断点恢复。
- 中文默认、英文可切换的响应式 Web 管理和浏览界面。
- 类抖音竖向沉浸浏览、视频播放、图集左右切换、收藏夹切换和搜索。
- Docker Compose 部署到 fnOS，并把数据与媒体持久化到 ZFS 数据卷。

首个版本不覆盖：

- 自动发布、评论、点赞或修改抖音账户数据。
- 绕过验证码、付费内容、私密内容或平台权限控制。
- 自动删除 NAS 文件来镜像抖音当前状态。
- 公网直接暴露管理页面。
- 将图文强制合成为 MP4；图文保留原始图片并在网页中以轮播浏览。

## 3. 推荐方案与取舍

采用“浏览器发现 + 独立下载”的混合方案。

- 纯接口方案请求最轻，但依赖签名算法和私有接口参数，抖音改版后维护成本最高。
- 纯浏览器方案不需要维护签名，但长时间逐个媒体下载会占用更多内存，失败恢复也较弱。
- 混合方案让 Playwright Chromium 负责扫码登录、加载官方收藏页面和捕获收藏数据；媒体 URL 交给独立下载器完成 Range 下载、重试、完整性检查和落盘。它避免自行保存抖音密码，也把最容易变化的平台适配集中在一个 provider 模块中。

## 4. 系统结构

单个 Docker Compose 应用包含以下进程：

1. `api`：FastAPI 服务，提供管理 API、浏览 API、媒体 Range 响应和健康检查。
2. `worker`：执行收藏发现、下载、重试、目录投影和完整性校验。
3. `scheduler`：每 5 分钟创建增量同步任务，并在低频时段创建完整校验任务。
4. `auth-browser`：按需启动的 Playwright Chromium。登录完成后关闭浏览器，不常驻占用资源。
5. `web`：React/Vite 构建的静态前端，由 API 同源提供。

部署时这些逻辑可以位于同一镜像，但代码边界和进程入口必须独立。SQLite 只允许一个迁移入口，启用 WAL 模式；worker 和 API 通过短事务访问数据库。

## 5. 登录与安全

### 5.1 管理员登录

首次打开网页时创建本地管理员密码，不提供默认密码。密码使用 Argon2id 哈希保存，登录态使用 `HttpOnly`、`SameSite=Strict` Cookie。所有修改性接口要求 CSRF Token。

### 5.2 抖音扫码登录

用户点击“登录抖音”后，后端启动一个临时 Chromium context 并进入抖音登录页。前端轮询显示浏览器截图中的二维码和登录状态。首版只支持扫码流程；如果平台要求验证码或其他交互，会明确结束本次登录并提示用户重新尝试，不会尝试绕过验证。

登录成功后：

- 只导出 `douyin.com` 必需 Cookie；
- 使用 `ARCHIVE_MASTER_KEY` 通过 Fernet 加密后写入数据库；
- 清理临时浏览器 profile；
- 立即关闭临时浏览器；
- 不保存抖音账号密码。

Cookie 失效时暂停发现任务但保留下载队列，网页显示“需要扫码”，并通过可选 Webhook/Bark 通知。用户重新扫码后自动恢复。

### 5.3 网络边界

服务仅绑定 fnOS 局域网地址，不自动配置端口转发。远程访问必须通过用户已有 VPN。日志、导出和 API 响应不得包含 Cookie、主密钥、完整媒体签名 URL 或管理员密码哈希。

## 6. 收藏发现与增量同步

平台访问封装为 `DouyinProvider` 接口，业务层不直接依赖 DOM 选择器或抖音响应字段。

```python
class DouyinProvider(Protocol):
    async def validate_session(self) -> SessionState: ...
    async def list_collections(self) -> list[RemoteCollection]: ...
    async def iter_collection_pages(
        self, remote_id: str, *, full_scan: bool
    ) -> AsyncIterator[RemotePage]: ...
```

同步规则：

- 首次同步遍历每个收藏夹全部分页，按页提交发现结果，不能把全量数据一次性保存在内存。
- 增量同步从最新页开始；连续遇到 30 个已知作品后停止该收藏夹扫描。
- 每日执行一次较深扫描，每周执行一次完整校验，补齐临时风控或分页异常造成的遗漏。
- 作品以 `aweme_id` 全局去重；收藏夹成员关系单独记录，同一作品可以属于多个收藏夹。
- API 游标只用作同一次任务的断点，不视为永久稳定标识。
- 请求随机抖动并限制并发；遇到验证码、空页异常或连续 429 时进入冷却，而不是高频重试。

## 7. 存储模型

所有数据放在同一个 ZFS dataset 内，以保证硬链接可用：

```text
archive-root/
├── data/
│   ├── archive.sqlite3
│   └── secrets/
├── objects/
│   └── <aweme_id>/
│       ├── metadata.json
│       ├── video.mp4
│       ├── cover.jpg
│       └── images/001.webp ...
├── library/
│   ├── 想去的地方/
│   │   └── <标题>_<aweme_id>/...
│   └── 好看的美女/
│       └── <标题>_<aweme_id>/...
└── tmp/
```

`objects` 是唯一真实媒体存储；`library` 是按收藏夹呈现的硬链接投影。同一作品出现在两个收藏夹时不重复占用媒体空间。如果硬链接不可用，记录告警并回退到复制，绝不能用符号链接指向容器外不稳定路径。

下载先写入 `tmp/*.part`，完成 Content-Length 或可用的媒体校验后原子移动。数据库只能在原子移动成功后把文件标记为 `ready`。启动时自动恢复可重试任务并清理超过 24 小时的孤立临时文件。

文件和目录名进行 Unicode NFC 归一化，去除路径分隔符和控制字符，保留中文；冲突时始终附加 `aweme_id`。收藏夹重命名后创建新名称投影但保留旧目录内容，符合永久归档规则。

## 8. 数据库

核心表：

- `settings`：调度、语言、下载并发和通知设置。
- `auth_sessions`：加密 Cookie、有效状态和最后验证时间。
- `collections`：远端收藏夹 ID、当前名称、历史名称和同步游标。
- `items`：作品 ID、作者、文案、类型、发布时间、首次发现时间和原始元数据摘要。
- `collection_items`：收藏夹与作品的多对多关系、首次和最后发现时间。
- `media_files`：对象存储相对路径、大小、校验值、MIME 和状态。
- `download_jobs`：幂等任务、重试次数、下次执行时间和最后错误码。
- `sync_runs`：每次运行的阶段、计数、游标、耗时和结果。

所有路径在数据库中存相对于 `archive-root` 的 POSIX 路径。数据库备份不包含明文 Cookie。

## 9. Web 浏览体验

视觉与交互借鉴抖音的浏览节奏，但使用自己的名称、图标和颜色资产，不复制其商标或私有素材。

桌面端：

- 左侧固定导航：全部归档、收藏夹、下载任务、同步状态、设置。
- 中间为 9:16 主播放器，滚轮或方向键上下切换作品，使用 CSS scroll snap。
- 右侧显示作者、文案、归档时间、来源收藏夹和本地文件状态。
- 图文作品在主区域左右滑动，支持缩略图和原图查看。

移动端：

- 全屏单列沉浸流；
- 上下滑切换作品，左右滑切换图集；
- 收藏夹使用底部抽屉切换；
- 控件尊重安全区和触摸尺寸。

播放器使用本地媒体 Range 请求，支持断点拖动。列表采用游标分页和窗口化渲染，不一次加载全库。默认中文，所有用户可见字符串进入 i18n 资源文件。

## 10. API 边界

首版 API：

- `POST /api/setup`：首次创建管理员。
- `POST /api/session`、`DELETE /api/session`：管理登录。
- `POST /api/douyin/login`：启动扫码登录。
- `GET /api/douyin/login/{id}`：返回状态和经过裁切的登录截图。
- `POST /api/douyin/login/{id}/cancel`：关闭登录会话。
- `POST /api/sync`：手动创建同步任务。
- `GET /api/sync/runs`：查询同步历史。
- `GET /api/collections`：收藏夹列表与数量。
- `GET /api/feed`：按收藏夹、关键词和类型分页查询归档作品。
- `GET /api/items/{aweme_id}`：作品详情。
- `GET /api/media/{file_id}`：鉴权后的 Range 媒体响应。
- `GET /api/jobs`、`POST /api/jobs/{id}/retry`：任务状态和重试。
- `GET /health/live`、`GET /health/ready`：进程和依赖就绪状态。

错误响应使用稳定的机器码，例如 `AUTH_REQUIRED`、`DOUYIN_SESSION_EXPIRED`、`RATE_LIMITED`、`MEDIA_GONE`、`STORAGE_FULL`，前端不得解析日志文本判断状态。

## 11. 测试与验收

测试分层：

- 单元测试：路径清理、硬链接投影、增量停止、去重、加密、Range 解析和状态机。
- Provider 契约测试：使用脱敏 JSON/HTML fixture 验证抖音字段变化的兼容层。
- 集成测试：临时 SQLite、假媒体服务器、失败重试、进程重启和原子落盘。
- 前端测试：收藏夹切换、竖向切换、图集切换、登录状态和中英文。
- Docker 冒烟：构建镜像、启动 Compose、健康检查、持久卷重启。
- NAS 验收：实际部署、打开管理页、用户扫码、读取真实收藏夹名称、下载一条新收藏并从网页播放。

完成标准必须分开报告：

1. 本地测试与构建结果。
2. NAS 镜像部署和进程健康。
3. 用户扫码后的真实账号登录。
4. 真实收藏夹发现与目录映射。
5. 实际媒体下载、文件完整性和网页播放。
6. 新增收藏在 10 分钟内归档的端到端结果。

扫码前只能声明前两项，不能把健康检查当作真实同步完成。

## 12. 部署与恢复

Compose 使用固定镜像标签和显式健康检查。`archive-root`、数据库和主密钥均使用 NAS 持久目录；镜像升级不得覆盖它们。升级前自动创建 SQLite 在线备份和配置快照。

容器以非 root UID/GID 运行，只获得归档 dataset 的读写权限。磁盘剩余空间低于配置阈值时暂停新下载并告警，不删除旧文件。回滚通过固定旧镜像标签与数据库备份完成。

## 13. 实施顺序

1. 建立后端骨架、配置、安全存储和数据库迁移。
2. 实现对象存储、目录投影、下载队列和媒体 Range API。
3. 实现 Playwright 扫码登录和 Cookie 加密续期。
4. 实现收藏 provider、全量/增量扫描和调度器。
5. 实现管理页与类抖音浏览网页。
6. 完成 Docker/Compose、NAS 部署和扫码前验证。
7. 用户扫码后完成真实端到端验收。

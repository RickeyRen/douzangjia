# 影仓部署、可观测性与验收设计

## 目标

在不破坏 NAS 上专用 Chromium profile、现有媒体和数据库的前提下，将影仓以可回滚的方式升级，并为功能、响应式布局、性能和实际下载建立端到端证据。

## 运行指标

后端采集并持久化下列时序样本，默认保留 7 天：

- 容器进程 CPU 使用率和 RSS 内存。
- NAS 数据卷总空间、可用空间、影仓媒体占用。
- 活动下载数、队列深度、瞬时及滚动平均速度。
- 同步中、不完整、失败来源数与会话健康状态。

API 为 `GET /api/metrics/current`, `GET /api/metrics/history?range=`, `GET /api/events/stream`。

## 数据库与部署安全

- 所有架构改动通过只向前的新 migration 实现，不修改已发布 migration。
- 部署前创建数据库备份并记录当前镜像 ID；不备份、复制或输出 Chromium profile。
- 健康检查必须区分：容器活着、API 可用、已登录会话、真实数据读取、真实媒体落盘。
- 镜像只保留有意义的当前版本和一个已知可回滚版本，清理不影响运行容器与数据卷。

## 测试层级

1. **后端单元/集成**：migration、repository、provider normalizer、游标终止规则、幂等任务、指标汇总。
2. **前端组件**：路由、tab、视图切换、三游标无限滚动、任务进度、响应式导航。
3. **构建与静态检查**：Python 全量测试，frontend test/lint/build。
4. **Chrome 端到端**：使用用户已登录的 Chrome 检查我的、关注和实际内容数据；使用同一浏览器检查影仓桌面与 iPhone 15 Pro Max 视口。
5. **真实归档**：从可识别的已登录来源选取一项，验证任务进度、媒体文件存在、字节数非零且 API 能播放。

## 性能预算

- 本地已缓存首页在家庭局域网中的 API P95 目标不高于 500ms。
- 滚动期间不使用全页截图传输；网格渲染的可见 DOM 卡片保持有界。
- 指标事件流默认 1 秒级更新，不将 250ms 轮询作为常规模式。

## Git 与交付

- 每个通过验证的独立阶段创建本地 checkpoint commit 和带时间戳的 annotated tag。
- 只有在远程确认为用户批准的私有 GitLab 时才推送当前分支和新标签；不 force push，不删除远程历史。
- 推送前检查不含 cookie、profile、`.env`、数据库、媒体、缓存和构建产物。

## 验收

- 新镜像在 NAS 启动后保留原会话和媒体，不要求用户重新扫码。
- 上述五层测试分别报告，不用 health check 代替登录、数据和真实下载证据。
- 若未配置批准的私有 GitLab 远程，保留本地 checkpoint 并如实说明未推送。

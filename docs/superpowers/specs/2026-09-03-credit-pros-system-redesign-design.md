# 抖藏家 Credit Pros 全站视觉重构设计

## 目标

将抖藏家从通用深色管理界面重构为以 RondesignLab「Credit Pros SaaS Dashboard」案例为唯一主视觉参考的专业视频归档产品。首页必须呈现真实 NAS、下载、同步、账号和媒体库数据；收藏、博主、视频详情、任务抽屉和登录流程使用同一套视觉语言；桌面和 iPhone 15 Pro Max 均须完整可用。

参考案例：https://rondesignlab.com/cases/credit-pros-saas-dashboard-ui-ux-design

本项目只复刻其视觉规律与信息组织，不复制 Credit Pros 的品牌、文案、图标、图片、插画或业务数据。

## 设计原则

1. 纯黑空间：页面底色接近 `#050505`，用 `#0B0C0F`、`#101115`、`#15161B` 建立层级，不使用大面积浅色卡片。
2. 极细边界：卡片通过 1px 半透明白色边框、局部内高光和深色阴影区分，而不是厚重描边。
3. 局部光晕：蓝色、紫色、黄色、绿色和红色只作为数据语义色与局部环境光。禁止整页统一染成绿色，也禁止无语义的全局紫蓝渐变。
4. 清晰层级：页面标题使用轻到中等字重和大字号；指标数字明显大于标签；辅助信息保持克制，但中文正文不得小于 13px。
5. 真实数据优先：每张图表、进度条、状态点、数量与活动列表都由现有 API 数据驱动。没有数据时显示明确的积累中、空状态或不可用状态，不制造演示数据。
6. 视频优先：统计首页使用 Credit Pros 式仪表盘；媒体库仍保留抖音式单视频浏览与高密度网格浏览。
7. 双主题：暗色为默认和完整主设计；亮色保留可切换能力，并使用独立的高对比中性色，不做机械反色。

## 全局视觉系统

### 色彩

- 暗色画布：`#050505`
- 一级表面：`#0B0C0F`
- 二级表面：`#111216`
- 悬浮表面：`#16181D`
- 主文字：`#F4F3EF`
- 次文字：`#A09FA5`
- 弱文字：`#686970`
- 边界：`rgba(255,255,255,.075)`
- 蓝色状态：`#4D7CFF`
- 紫色状态：`#9A5CFF`
- 黄色状态：`#FFD84D`
- 绿色状态：`#54E68B`
- 红色状态：`#FF5B67`
- 青色状态：`#5EE7D7`

状态色必须语义化：绿色仅表示健康/完成，红色表示失败/远端删除，黄色表示等待/告警，蓝色表示下载，紫色表示同步。

### 字体与密度

使用现有可本地加载的 Geist/PingFang SC 字体栈，不引入远程字体依赖。桌面页标题 30–36px，区块标题 18–22px，核心指标 30–44px，正文 14–15px，标签 12–13px。数字使用 tabular numbers。桌面卡片圆角 20–24px，控件圆角 12–16px，移动端卡片圆角 18–22px。

### 图标与动效

继续使用 Phosphor Icons，但从彩色方形 icon well 改为小型圆形状态点、深色图标按钮和少量彩色光晕。交互过渡 160–240ms；下载与同步使用低强度呼吸/扫描动效；遵守 `prefers-reduced-motion`。

## 页面架构

### 桌面应用外壳

采用 72px 收拢图标栏 + 220px 上下文导航 + 自适应主内容的三级结构。图标栏承载首页、收藏、搜索、活动和设置；上下文导航展示账号信息、收藏类别及每类下载圆环；主内容根据页面切换。右侧视频详情仅在沉浸单视频模式出现。

顶部栏保持 68–76px 高，包含当前页面标题、全局搜索、账号健康状态、主题切换和账号头像。所有页面共享外壳，避免当前首页和收藏页像两个产品。

### 首页

首页使用 12 列 Bento 栅格：

- 顶部欢迎区：抖音昵称、抖音号、会话健康、最后更新时间。
- 主状态卡：当前正在执行的同步/下载动作、来源名称、实时速度、总进度和立即打开任务入口。
- 四个首要指标：归档空间、下载速度、CPU、内存。
- 双图表：下载吞吐趋势、系统负载趋势，使用真实 SSE 历史点。
- 存储卡：归档占用、磁盘已用/剩余及环形占比。
- 队列卡：等待、下载、重试、失败、完成数量和总进度。
- 抖音账号卡：头像、昵称、抖音号、会话健康、最近验证、最近同步。
- 收藏来源进度：每个来源的发现数、已归档数、下载进度和同步状态。
- 服务运行详情：应用、下载器、同步浏览器的状态和内存。

首页首屏在 1440×900 下必须看到当前活动、四项核心指标和至少一组趋势图，不再连续堆叠十多个同权重区块。

### 收藏与媒体库

- 单作品模式：中央 9:16 媒体舞台，右侧为作者与文件信息，底部/侧边为切换和下载操作。
- 多作品模式：桌面 4–6 列自适应封面网格，移动端 2 列；滚动接近底部自动加载，不要求用户点击。
- 卡片显示本地状态、媒体类型、标题、作者和抖音号；信息通过渐变遮罩保证可读性。
- 搜索、视图切换、当前类别下载入口在统一顶部工具栏中。

### 博主主页

采用抖音主页的信息结构并套用 Credit Pros 视觉语言：头像、昵称、抖音号、远端作品数、粉丝数、本地归档数、订阅状态、全部归档按钮和作品网格。远端身份刷新中、不可用和失败必须有不同状态。

### 视频详情与任务抽屉

详情面板显示作者、抖音号、描述、发布时间、收藏分类、本地路径、文件大小、分辨率、编码、下载状态和远端删除状态。下载/同步/活动/设置继续作为抽屉出现，但统一为圆角深色浮层，进度、失败原因和操作按钮可直接辨认。

### 登录、初始化与错误页面

本地账户设置、用户名密码登录和抖音登录使用与主应用一致的纯黑背景、居中深色面板、品牌光晕和大号标题。错误、加载、空状态不得缩成页面角落的小字；需要占据清晰的视觉中心并提供 44px 以上操作按钮。

## 响应式设计

- `>= 1280px`：完整三级桌面外壳。
- `768–1279px`：收起上下文导航，保留图标栏；详情使用抽屉。
- `< 768px`：顶部紧凑栏 + 底部五项导航；无固定侧栏。
- iPhone 15 Pro Max 以 430×932 CSS 像素验收，正确处理安全区、键盘、底部导航和全屏媒体。
- 中文与英文均不得造成标题、抖音号、文件名、进度数字互相覆盖。

## 数据与状态

不修改后端数据模型。`FeedPage` 继续持有页面、来源、视图、作者和详情状态；`useDashboardStream` 继续提供首页及导航中的实时数据。视觉组件只能消费现有 API 类型，不复制轮询逻辑。SSE 断开时保留最后快照并显示离线状态；首次加载失败显示可操作的重试页面。

## 组件边界

- `AppShell`：全局桌面/移动布局和导航插槽。
- `PrimaryRail`：顶层目的地、头像与连接状态。
- `CollectionRail`：收藏来源、来源进度和任务进度。
- `DashboardHero`：账号与当前实时活动。
- `MetricCard` / `TrendCard` / `StorageCard` / `QueueCard`：真实数据可视化。
- `MediaToolbar`：搜索、来源名称、视图切换和归档动作。
- `CreatorProfile`：博主身份、统计和动作。
- `DetailPanel`：视频与本地文件详情。
- `StatusDrawer`：下载、同步、活动、设置内容容器。

## 错误处理与无障碍

所有颜色状态同时提供图标或文字；文本对比度目标达到 WCAG AA；交互目标至少 44×44px；抽屉具备 dialog 语义；进度具备 progressbar 语义；键盘 focus ring 清晰。图片缺失、身份缺失、历史数据不足、服务不可用和网络错误均有稳定布局。

## 验收标准

1. 暗色首页在 1440×900、1280×800 和 430×932 均无截断、覆盖或不可见标题。
2. 首页所有指标来自现有 dashboard/SSE 数据，当前活动在一秒级更新。
3. 收藏单作品、多作品、博主页、详情抽屉、下载、同步、设置、登录与错误页均采用同一视觉系统。
4. 每个视频仍显示作者和抖音号；缺失时保留刷新状态而非伪造 ID。
5. 原有 76 个以上前端测试通过，并新增视觉结构、响应式类名与关键状态测试。
6. `npm test`、`npm run build`、`npm run lint` 通过；后端回归测试通过。
7. 使用真实生产数据完成桌面与 iPhone 15 Pro Max 浏览器截图验收。
8. 部署到 NAS 后容器健康，`http://192.168.0.6:8099/` 可访问，现有数据库、归档目录、`.env` 和 Chromium 登录配置不被覆盖。

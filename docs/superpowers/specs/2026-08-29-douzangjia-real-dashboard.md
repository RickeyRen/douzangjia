# 抖藏家真实运维首页设计规格

## 目标

把抖藏家首页重构为与参考 Remnawave 首页同等信息密度和视觉完成度的深色运维仪表盘，同时保证每个数值都有可追溯的真实数据来源。桌面端以横向统计带和三列 Runtime 为主；iPhone 15 Pro Max 以同一语义的移动端兄弟布局呈现，不把桌面页面简单缩小。

## 已接受的视觉参考

- 参考页面：`https://remnawave.siphase.com/dashboard/home`
- 桌面规格：`docs/designs/douzangjia-dashboard-desktop.png`
- 手机规格：`docs/designs/douzangjia-dashboard-mobile.png`
- 参考页面仅用于布局语言、信息密度、色彩角色、卡片边界和 Runtime 结构。不得复制 NodeBrighton 品牌、文字或受保护资产。
- 概念图内示例数字只定义排版，不进入生产数据、测试夹具或回退逻辑。

## 真实数据契约

### 归档引擎使用情况

- 服务数量：固定为当前程序确实拥有的三个逻辑运行单元——应用服务、下载引擎、抖音同步浏览器。
- 应用内存：读取当前 Python 进程 RSS。
- 浏览器内存与进程数：遍历当前 Python 进程的 `/proc` 子进程树，只累计命令行包含 Chromium/Chrome 的实际 RSS；不可用时返回 `0` 和 `0`，界面显示不可用而不是猜测。
- 当前下载速度：下载队列中最近五秒仍活跃的媒体速度总和。
- CPU：显示系统 1/5/15 分钟 load average 和按 CPU 核数归一化的当前负载百分比。

### 归档吞吐

- 今天、最近 7 天、最近 30 天：按 `media_files.completed_at` 统计 `status='ready'` 的 `byte_size`。
- 对比昨日、上周、上一个 30 天窗口：使用相同长度的前一时间窗。
- 只有 `MIN(completed_at)` 早于对比窗口起点时，`comparisonAvailable=true`；否则界面显示“数据积累中”。
- 累计归档：所有 `status='ready'` 媒体的真实 `byte_size` 总和。
- 日界线按 `Asia/Shanghai` 计算。

### 队列、NAS、资料库和账号

- 队列：等待、下载中、重试、失败、已完成全部来自 `download_jobs`。
- NAS：总量、已用、可用来自 `shutil.disk_usage`；归档量来自 ready 媒体字节之和。
- 资料库：发现作品、已归档作品、媒体文件、创作者和来源分类来自 SQLite 聚合。
- 抖音账号：昵称、抖音号、健康状态、最后验证、最后同步来自 `AccountHealthService`；缺失字段显示“暂未获取”。

### Runtime

- 应用服务：Python RSS、系统 CPU 负载、服务运行时间、最近生成快照时间。
- 下载引擎：配置 worker 数、存活 worker 数、当前下载数、等待/重试数、速度、最近任务更新时间。
- 同步浏览器：Chromium 进程数和 RSS、浏览器是否启动、页面租约是否忙、账号健康、最后同步时间。
- 下载引擎是同一 Python 进程中的异步 worker，因此不得伪造独立进程内存。

## 页面结构

1. 紧凑顶栏：抖藏家、账号、实时/中断状态、最后更新时间、主题切换。
2. 归档引擎使用情况：四格横向指标带。
3. 服务详情：三个逻辑服务状态。
4. 归档吞吐：今天、7 天、30 天、累计。
5. 队列状态：等待、下载中、重试、失败、完成。
6. NAS 系统：归档、磁盘、内存、CPU。
7. 资料库：发现、归档、媒体、创作者、来源。
8. 抖音账号：身份、健康和同步时间。
9. 收藏分类进度：点击进入来源；显示归档/发现、空间、待处理和真实完成度。自动下载开关移到来源管理界面，首页只做总览。
10. Runtime：三张颜色区分的详细运行卡。

## 视觉系统

- 暗色画布：`#161b22`；表面：`#1b2028`；细边框：`#252b35`。
- 主文字：`#c9d1d9`；次文字：`#8b949e`；弱文字：`#6e7681`。
- 色彩角色：蓝=应用/资料，紫=下载，绿=健康/浏览器，青=存储，橙=吞吐/等待，红=失败。
- 半径 8–12px；仅用轻微内阴影，不使用玻璃拟态、大面积渐变或绿色单色系统。
- UI 使用现有字体栈；数值使用 `Geist Mono`/系统等宽字体。
- 重要数值无需 hover；所有图标继续使用现有 Phosphor duotone 家族。

## 实时与失败状态

- SSE 每秒用完整快照替换实时状态，趋势序列仍由持久化采样提供。
- 断线时保留最后一次成功快照和图形，状态切换为“连接中断”，显示最后更新时间。
- 无历史点、无账号字段、无浏览器进程或未知远端总数都使用明确缺失状态，不生成基线或 100% 假完成度。
- 动画只用于连接状态呼吸和短暂数值过渡；`prefers-reduced-motion` 下停用。

## 可视化技术设计

- 分析任务：近实时监控、当前与历史比较、队列异常发现。
- 数据形态：快照 + 24 小时时间序列 + SQLite 窗口聚合。
- 同时可见图形：最多两个轻量 SVG 趋势图和若干 CSS 进度环；不引入图表库。
- React 负责数据状态、布局、标签、空态和响应式；SVG 仅负责折线几何，所有关键值保留为 DOM 文本。
- 每张趋势图最多消费已有持久化采样点；不会增加新的高频前端定时器。
- 移动端不提供拖拽或 hover 交互，避免劫持页面滚动。

## 响应式契约

- 桌面：`>=1200px`，四/五列统计带，Runtime 三列，内容使用完整可用宽度。
- 平板：`720–1199px`，两列或三列，Runtime 单列/双列。
- 手机：`360–430px`，首屏先显示账号、连接、四格引擎概览和队列摘要；其余区块按优先级纵向排列。
- iPhone 15 Pro Max 验收视口：`430×932`；尊重顶部和底部 safe-area。
- 触控按钮最小 44px；页面无水平溢出；分类列表可纵向阅读，不能依赖横向滚动才能看到关键值。

## 验收标准

- 后端单元/API 测试覆盖真实吞吐窗口、比较可用性、Chromium 进程统计和 Runtime 契约。
- React 组件测试覆盖全部十个区块、真实值格式、断线保留、账号缺失、分类点击和多色图标角色。
- lint、TypeScript build、前后端全量测试和 `git diff --check` 通过。
- 内置浏览器完成桌面、当前窗口和 430×932 视觉检查；若内置浏览器无法设置精确视口，必须如实记录并用项目现有浏览器测试补足，不能声称已验证。
- NAS 部署后接口和页面使用真实生产数据库，容器健康，不覆盖登录 profile、`.env` 或归档数据。

# 持续开发目标：像真实用户一样用抖藏家，找出并修好难用的地方

上一个目标（消失博主的互联网存档）已归档到 `docs/goals/2026-11-vanished-creators.md`，其中只剩用户亲手做的两项。

## 目标

把自己当成每天用抖藏家刷收藏的用户，同时用网页版和 iPhone 模拟器版，持续找出卡、慢、难用、不符合直觉的地方，修好并验证。

## 完成标准

全部满足才算完成：

1. 播放：竖屏全屏一条一条上下滑着看；滑到下一条立即开始播放，上一条停止；单击暂停/继续；进度条可拖动；能看到博主、文案，能回到博主存档主页。网页用滚轮和方向键也能上下切换。
2. 速度（在 NAS 线上实测，不算第一次冷启动）：网页和 App 首页 1 秒内出现内容；作品页首屏 1 秒内出现封面；点开作品 1.5 秒内开始播放；翻页和滑动没有明显卡顿。
3. 网页和 App 的每个主要页面（首页、作品、博主存档、下载、设置、播放）各完整走过一遍用户流程，发现的问题都修好或明确记录为暂不修。
4. 连续两轮巡检没有发现新的严重问题（卡死、白屏、无法播放、数据显示错误、明显慢于上面的标准）。
5. 用户在真机上确认过播放体验。

## 每一轮怎么做

1. 先看线上健康状况（容器、同步、下载），再像用户一样用一遍网页（线上 NAS）和 App（项目模拟器 `Douzangjia QA iPhone 17 Pro`，连线上 NAS 或本机测试后端），记下耗时和问题。
2. 新发现的问题按严重程度插进待办，再从上往下取一项来做。
3. 写代码和测试，全部通过后提交，推送到 `origin main`。
4. 需要上线时：先备份数据库并给旧镜像打回滚标签，等同步空闲再切换。
5. 界面改动要看到真实画面再算完成；App 有改动就发一版 TestFlight。
6. 勾掉待办，把结果和实测数字记到下面的进展记录。
7. 一轮结束关掉本轮开的模拟器和测试服务器。

## 必须停下来问用户的情况

- 需要用户登录、授权或做真机验收
- 可能删除或覆盖用户数据，或要动 `.env`、`compose.yaml`
- 提交 App Store 审核或对外公开任何内容
- 触发抖音限流、验证码，或抖音登录失效（不绕过验证码）
- 设计方向上有两种都说得通的做法、且改动大
- 同一个问题连续两轮没有进展

## 进展记录

- 2026-11-10：目标建立。用户反馈：播放界面难用，和抖音的上下滑逻辑不一样；整体加载非常缓慢。
- 2026-11-10：线上实测慢的根因：所有读查询共用一个读连接，首页全库统计（重启后 64 秒）和后台任务一占住，其它请求全部排队。NAS 本身内存和交换区用满、负载 21，磁盘被下载占满，查询时快时慢。改成 4 个读连接，首页统计改为扫覆盖索引后在 Python 里计数，并加了慢事务日志和完整的任务等待链（62577ec）。线上前后对比：`/api/status`（每个页面先等它）20 秒→0.01 秒；下载进度 16 秒→0.2 秒；打开作品详情 90 秒超时→0.01 秒；首页热 0.2 秒、重启后首次 64 秒→约 13 秒；收藏列表 90 秒超时→0.06 秒。
- 2026-11-10：用线上数据库副本加 400 个真实文件在本机搭了测试环境（去掉抖音登录状态，不跑后台任务）。网页播放器问题：切换是瞬间替换没有滑动动画、手机上手指不跟随；只有一个 video，下一条不预加载；详情面板默认占四分之一屏且开着时画面上不显示作者文案；默认播完自动跳下一条（抖音是单条循环）。App 的 VideoPlayer 是系统控件，单击弹出系统控制条而不是暂停，没有细进度条，不能点作者进主页。
- 2026-11-10：网页播放器改成三页竖向轨道：手指拖动跟随、松手按距离或速度翻页、滚轮一次手势只翻一条、下一条视频提前缓冲、默认单条循环、详情面板默认收起、作者文案常显、右侧头像/精选/详情栏，偏好换成 v2 键名（c2f73a1）。本机 1440 宽和手机宽都实测过：翻页后上一条暂停并静音，下一条已缓冲。App 用 AVPlayerLayer 自绘画面，单击暂停/继续带播放图标，底部细进度条可拖动、拖动时显示时间，点头像或 @作者 在播放器里打开博主存档、返回回到原视频（9ca93e4），模拟器上逐项看过真实画面。巡检中发现博主存档页对没改过名的博主也显示“原来的资料”提示，已记入待办。
- 2026-11-10：巡检第 1 轮。线上健康，12 小时内没有慢事务，只有 3 次抖音页面被关掉的报错。首页统计现在 1.4 秒、整个首页 1.8 秒；加了列表计数覆盖索引。修了 App 博主存档页对正常博主误显示“原来的资料”和重复的资料变化，模拟器上看过真实画面；TestFlight 第 14 版。
